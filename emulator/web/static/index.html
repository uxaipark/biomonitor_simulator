    101 · 처음 시작 5분이면 첫 전송까지
    
        
    1. 시작 버튼
    
          
          
          
    1. 오른쪽 위 ▶ 시작을 누릅니다.
    2. 두 번째 줄 칩이 실행 중, pkt/s가 0보다 크면 성공입니다.
    3. ■ 정지를 누르면 파형 생성과 화면 갱신이 모두 멈춥니다.
    
          
    처음이면 1시간 루프 파일이 먼저 만들어집니다(Pi4 5~10분). 대시보드에 진행률이 보입니다.
    
        
    2. 시나리오 탭에서 규모 정하기 
    
          
          
    1. 모니터링 환자 수: 50 · 100 · 200 · 500 · 1000 · 2000 중 하나를 누릅니다.
    2. MCOT 환자 수(원외): 10 · 50 · 100 · 200.
    3. 상단 칩 환자 n / 패치 연결 n으로 확인합니다. 바로 반영됩니다.
    
        
    3. 전송 탭에서 라우터 서버 붙이기 
    
          
          
    1. 서버 IP와 포트(기본 9100)를 입력합니다. IP를 비우면 "생성만"(전송 없음).
    2. 라우터가 없으면 참고 수신기로 확인: python tools/receiver.py --port 9100 후 IP에 127.0.0.1.
    3. 전송 통계의 백로그 드롭·미연결 드롭이 0에 가까우면 정상입니다.
    
        
    4. 신호 탭 둘러보기 
    
          
          
    1. 환자 검색(이름·병상·MRN) 후 선택.
    2. 위쪽 동그란 체크는 모든 환자의 전송 채널 스위치입니다.
    3. 수치 카드 끝 ▸ 버튼: 1·2·3일 추세 그래프.
    
        
    5. 환자 탭 둘러보기 
    
          
          
    1. 열 이름 클릭 = 정렬, 검색은 이름·환자번호·리듬·병동·진료과·패치.
    2. 행을 누르면 오른쪽에 상세(페이스메이커·기기 세트·패치 이력).
    
        
    6. 병원 탭 둘러보기 
    
          
          
    1. 측면도의 층을 누르면 도면이 바뀝니다. 도면 클릭 = 확대, 드래그 = 이동.
    2. 환자 아이콘 → 신호 탭, 게이트웨이 아이콘 → 중앙 모니터.
    3. 표시 모드 게이트웨이 음영지역은 전파 사각지대를 빗금으로 보여 줍니다.
    
        
    7. 중앙 모니터 열어 보기
    
          
          
    1. 헤더 Auto 또는 n-up 드롭다운으로 격자를 고릅니다.
    2. 종 아이콘 = 알람 묵음 토글, ↻ = 다시 불러오기, Close = 닫기.
    3. 타일을 누르면 단일 침상 뷰어가 열립니다.
    
          
    
        
    8. 로그와 저장
    
          
          
    1. 설정은 바꾸는 즉시 저장됩니다(data/config.json).
    2. ☀️/🌙 버튼으로 테마 전환.
    
      
    

      
    
        
    201 · 시나리오 조작 장애·아티팩트·이벤트 주입
    
        
    시나리오 탭 카드 한눈에
    
          
    1. 운영 형태 병원/원외/혼합, 리듬 에피소드(발작성 부정맥), 변형 순환(시간 반복 방지).
    2. 기기 세트: 증상별 자동 배정, SpO₂ 센서 비율.
    3. 네트워크 장애·아티팩트·패치·게이트웨이 장애 카드: 체크 + 강도 슬라이더. 각 카드의 버튼은 즉시 1회 주입.
    
        
    특정 환자에게 이벤트 주입 (신호 탭)
    
          
    1. 스위치 켜기 = 리드오프 60초 · 부정맥 180초 · 심실세동 120초 · MRI 이동(단계·남은 시간 표시).
    2. 시간이 끝나면 자동으로 풀리고, 끄면 즉시 취소됩니다.
    3. 패치 교체·퇴원 버튼도 같은 카드에 있습니다. MRI 후에는 패치 번호가 바뀝니다.
    
        
    중앙 모니터 알람 읽기
    
          
    1. 적색: VFib · VT · 무수축 · 3도 차단 · SpO₂<88 · HR>150/<40 · NIBP≥190/<80 · 신호 없음.
    2. 황색: AFib 등 리듬 · 리드오프 · 한계 이탈(HR 50–120, RR 8–30, SpO₂≥90, NIBP 90–160, 체온 <38.3) · 배터리 ≤15 %.
    3. 12-up 이상은 수치가 2열 매트릭스로, 48 초과는 숫자 전용 보드로 바뀝니다.
    
        
    데이터 탭 
    
          
          
    1. 구조 설정(병상 수·프로필·시드)은 바꾼 뒤 [병원·환자 재구성].
    2. 패치 레지스트리: 발급된 모든 패치 이력, 열 정렬.
    3. SQLite DB: 읽기 전용 SQL. 예 SELECT ward, COUNT(*) FROM admissions WHERE discharged_at IS NULL GROUP BY ward
    
        
    프로토콜 탭 
    
          
          
    1. 라우터는 이 문서와 GET /api/v1(디스커버리 JSON)을 기준으로 구현합니다.

    T-01 기본 병동 모니터링 (기준선) 
    
      
    장애 없이 200명 스트림이 안정적으로 들어오는지.
    1. 적용 후 시작 버튼이 켜져 있는지 확인.
    2. 수신기에서 gws·patches 수가 안정되는지 1분 관찰.
    확인 포인트 프레임/초 ≈ 게이트웨이 수 × 5, 드롭 0, 오류 GW 0.
    
        
    T-02 무선 노이즈·간섭 
    
      
    BLE/무선 구간 잡음으로 손실·지연·지터가 섞인 스트림.
    1. 상단 칩 NET 장애 ON 확인.
    2. 로그 탭에서 "무선 노이즈/간섭" 이벤트가 층 단위로 생기는지.
    확인 포인트 라우터가 seq gap을 손실로 집계하고 늦게 오는 프레임을 버리지 않는지.
    
        
    T-03 유선 장애 · 순간 정전 
    
      
    한 층 또는 한 동의 게이트웨이가 동시에 끊겼다가 복구.
    1. 복구 시 저장 후 전송 버스트가 도착합니다(전송 탭 통계 재전송 프레임).
    2. 라우터 접속 수가 떨어졌다가 돌아오는지.
    확인 포인트 복구 후 과거 타임스탬프 프레임이 순서대로 들어오고 중복이 없어야 함.
    
        
    T-04 네트워크 지연·지터 
    
      
    수백 ms 지연과 지터.
    1. 대시보드 게이트웨이 표의 지연 열을 봅니다.
    확인 포인트 라우터 타임스탬프 정렬·버퍼링 정책 확인.
    
        
    T-05 아티팩트 최대 
    
      
    움직임·샤워·검사 이동·재부착·전동·패치 교체·가정 간섭을 최대 빈도로.
    1. 신호 탭에서 파형 왜곡·리드오프·재부착 안정화 구간을 봅니다.
    2. 환자 탭 패치 이력에서 교체 기록을 봅니다.
    확인 포인트 레코드 flags(LEAD_OFF, MOTION, NEW_PATCH)와 패치 번호 변경 처리.
    
        
    T-06 패치 수명 가속 
    
      
    배터리를 30분 만에 소모시켜 교체·반납 사이클을 빠르게.
    1. 데이터 탭 패치 레지스트리에서 새 시리얼 발급을 봅니다.
    2. 중앙 모니터의 배터리 아이콘·BATTERY LOW 알람.
    확인 포인트 LOW_BATTERY 플래그 → 교체 → 새 patch_id로 스트림 이어짐, 번호 재사용 없음.
    
        
    T-07 게이트웨이 장애·교체 
    
      
    무응답·성능 저하·하드웨어 고장을 높은 빈도로.
    1. 병원 탭 도면에서 붉은 게이트웨이와 이웃으로 옮겨 붙는 환자.
    2. 교체 후 새 gw_no/MAC으로 META 재전송.
    확인 포인트 패치 핸드오버 시 patch_id 연속성, 새 gw_id 인식.
    
        
    T-08 부정맥 폭풍 
    
      
    에피소드 자동 발생 + 스크립트로 연속 주입.
    1. 스크립트 arrhythmia_sweep이 자동으로 시작됩니다(시나리오 탭 패널에서 진행 확인).
    2. 중앙 모니터 알람 헤더가 황색/적색으로 바뀌는지.
    확인 포인트 HR 수치 채널과 ECG 파형이 같은 리듬을 가리키는지, 페이스 마크 처리.
    
        
    T-09 원외(MCOT) 100명 
    
      
    휴대폰 게이트웨이, 가정 간섭, 이동.
    1. 대시보드의 MCOT 환자 수, 게이트웨이 유형 mobile.
    확인 포인트 모바일 게이트웨이(용량 1)의 잦은 재접속 처리.
    
        
    T-10 혼합 대규모 2000 + 200 
    
      
    최대 규모 부하.
    1. 대시보드 워커 표: overrun 0, build/send µs.
    2. 필요하면 전송 탭에서 워커 수·번들 주기 조정.
    확인 포인트 라우터 수신 프레임/초 ≈ 게이트웨이 수 × 5 유지, 소켓 수 = 게이트웨이 수.
    
        
    T-11 저장 후 전송 검증 
    
      
    장애 중 버퍼링 → 복구 후 버스트 재전송을 정답 캡처와 대조.
    1. 수신기를 --strict --save-frames recv/로 띄웁니다.
    2. 적용 후 [임의 게이트웨이 장애 90s]가 자동 주입됩니다.
    3. 끝나면 python tools/verify_capture.py --capture data/runtime/capture --received recv/.
    확인 포인트 missing 0 · duplicate 0, out_of_order는 재전송 구간에서만.
    
        
    T-12 파서 퍼징 
    
      
    프레임 1000개당 20개를 10종으로 오염.
    1. 엄격 수신기의 strict 줄에서 종류별 검출 수를 봅니다.
    확인 포인트 라우터 프로세스가 죽지 않고 재동기화, 오류 카운터 증가.
    
        
    T-13 연결 폭주 · 반열림 · gw_id 중복 
    
      
    접속 처리 내구성 3종을 한 번에.
    1. 적용과 함께 storm_drill 스크립트가 시작됩니다(캡처→네트워크→폭주→반열림→중복→장애→교체).
    2. 라우터의 동시 accept, 유휴 연결 타임아웃, 중복 ID 정책을 봅니다.
    확인 포인트 폭주 후 접속 수가 게이트웨이 수로 회복, 반열림 연결이 타임아웃으로 정리, 중복 ID 경고.
    
        
    T-14 채널 축소 전송 
    
      
    ECG·HR·SpO₂만 보내는 최소 채널 구성.
    1. 프로토콜 탭의 채널 마스크와 META channels_enabled 확인.
    확인 포인트 라우터가 채널 마스크 변경(META)에 맞춰 파서를 갱신하는지.
