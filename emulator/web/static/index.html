언제 · 어떤 순서로 쓰나요?

언제 병원 규모·건물 구성, 환자 구성(프로필 수·질환·국적·페이스메이커 비율), 게이트웨이 설치·용량, 파형 종류 자체를 바꿀 때와 같은 조건으로 결과를 재현해야 할 때 씁니다. 평소 테스트 조건(장애·아티팩트·환자 수·실제 시그널)은 [시나리오]에서 바꿉니다.
  1. 값 바꾸기 — 아래 카드에서 시드·프로필 수·템플릿·건물 수·게이트웨이 용량 등을 고칩니다. 병상 수는 [시나리오]에서 정합니다.
  2. [재구성] — 병원과 환자를 새로 짓습니다. 재원 환자·패치 상태가 초기화되고 라우터 연결이 몇 초 끊겼다가 자동으로 다시 붙습니다.
  3. [루프 은행 재생성] — 시드 · 리듬별 루프 변형 수 · 표본율을 바꿨을 때만. 수 분 걸리며 오른쪽 카드에 진행률이 보입니다.
  4. 재현 실행이면 시작 시각 고정과 1초 고정 간격을 켠 뒤 [재구성]합니다. 같은 시드·시각이면 같은 사건이 같은 순서로 다시 일어납니다.

    101 · 처음 시작 5분이면 첫 전송까지
    
        
    1. 시작 버튼
    
          
          
          
    1. 오른쪽 위 ▶ 시작을 누릅니다.
    2. 두 번째 줄 칩이 실행 중, pkt/s가 0보다 크면 성공입니다.
    3. ■ 정지를 누르면 파형 생성과 화면 갱신이 모두 멈춥니다.
    
          
    처음이면 1시간 루프 파일이 먼저 만들어집니다(Pi4 5~10분). 대시보드에 진행률이 보입니다.
    
        
    2. 시나리오 탭에서 규모 정하기 
    
          
          
    1. 모니터링 환자 수: 50 · 100 · 200 · 500 · 1000 · 2000 중 하나를 누릅니다.
    2. MCOT 환자 수(원외): 10 · 50 · 100 · 200.
    3. 상단 칩 환자 n / 패치 연결 n으로 확인합니다. 바로 반영됩니다.
    
        
    3. [에뮬레이터 설정 › 시그널 송출]에서 라우터 서버 붙이기 
    
          
          
    1. 서버 IP와 포트(기본 9100)를 입력합니다. IP를 비우면 "생성만"(전송 없음).
    2. 라우터가 없으면 참고 수신기로 확인: python tools/receiver.py --port 9100 후 IP에 127.0.0.1.
    3. 전송 통계의 백로그 드롭·미연결 드롭이 0에 가까우면 정상입니다.
    
        
    4. 모니터링 탭 둘러보기 
    
          
          
    1. 목록에서 환자를 누르면 오른쪽에 그 환자의 파형과 수치가 실시간으로 흐릅니다.
    2. 열 이름 클릭 = 정렬. 검색은 이름·환자번호·리듬·병동·진료과·패치. 상태 드롭다운으로 입원만·MCOT만 거를 수 있습니다.
    3. 수치 카드 끝 ⌄ 버튼: 1·2·3일 추세 그래프. 환자 정보 아래에는 입원 기록·검사·동선·패치 이력이 이어집니다.
    4. 모든 환자에 공통인 전송 채널 선택은 [에뮬레이터 설정 › 시그널 송출]으로 옮겼습니다.
    
        
    5. 병원 탭 둘러보기 
    
          
          
    1. 측면도의 층을 누르면 도면이 바뀝니다. 도면 클릭 = 확대, 드래그 = 이동.
    2. 환자 아이콘 → 모니터링 탭, 게이트웨이 아이콘 → 중앙 모니터.
    3. 표시 모드 게이트웨이 음영지역은 전파 사각지대를 빗금으로 보여 줍니다.
    
        
    6. 중앙 모니터 열어 보기
    
          
          
    1. 헤더 Auto 또는 n-up 드롭다운으로 격자를 고릅니다.
    2. 종 아이콘 = 알람 묵음 토글, ↻ = 다시 불러오기, Close = 닫기.
    3. 타일을 누르면 단일 침상 뷰어가 열립니다.
    
          
    
        
    7. 로그와 저장
    
          
          
    1. 설정은 바꾸는 즉시 저장됩니다(data/config.json).
    2. ☀️/🌙 버튼으로 테마 전환.
    
      
    

      
    
        
    201 · 시나리오 조작 장애·아티팩트·이벤트 주입
    
        
    시나리오 탭 카드 한눈에
    
          
    1. 운영 형태 병원/원외/혼합, 리듬 에피소드(발작성 부정맥), 변형 순환(시간 반복 방지).
    2. 기기 세트: 증상별 자동 배정, SpO₂ 센서 비율.
    3. 네트워크 장애·아티팩트·패치·게이트웨이 장애 카드: 체크 + 강도 슬라이더. 각 카드의 버튼은 즉시 1회 주입.
    
        
    특정 환자에게 이벤트 주입 (모니터링 탭)
    
          
    1. 스위치 켜기 = 리드오프 60초 · 부정맥 180초 · 심실세동 120초 · MRI 이동(단계·남은 시간 표시).
    2. 시간이 끝나면 자동으로 풀리고, 끄면 즉시 취소됩니다.
    3. 패치 교체·퇴원 버튼도 같은 카드에 있습니다. MRI 후에는 패치 번호가 바뀝니다.
    
        
    중앙 모니터 알람 읽기
    
          
    1. 적색: VFib · VT · 무수축 · 3도 차단 · SpO₂<88 · HR>150/<40 · NIBP≥190/<80 · 신호 없음.
    2. 황색: AFib 등 리듬 · 리드오프 · 한계 이탈(HR 50–120, RR 8–30, SpO₂≥90, NIBP 90–160, 체온 <38.3) · 배터리 ≤15 %.
    3. 12-up 이상은 수치가 2열 매트릭스로, 48 초과는 숫자 전용 보드로 바뀝니다.
    
        
    데이터 탭 
    
          
          
    1. 바이오 월드 생성(시드·프로필·템플릿)은 [에뮬레이터 설정 › 바이오 월드 생성]에서 바꾼 뒤 [재구성].
    2. 패치 레지스트리: 발급된 모든 패치 이력, 열 정렬.
    3. SQLite DB: 읽기 전용 SQL. 예 SELECT ward, COUNT(*) FROM admissions WHERE discharged_at IS NULL GROUP BY ward
    
        
    프로토콜 탭 
    
          
          
    1. 라우터는 이 문서와 GET /api/v1(디스커버리 JSON)을 기준으로 구현합니다.
    
        
    현장 재현 (디지털 트윈) 
    
          
    1. 네트워크 장애 카드: 층 스위치·무선 AP·건물 코어가 죽으면 그 아래 게이트웨이가 한꺼번에 업링크 단절됩니다. 패치는 붙은 채 프레임이 쌓였다가 복구 때 올라갑니다. [건물 정전]은 UPS·발전기·일반 전원 계통별로 다르게 복구됩니다.
      2. 
          
    2. 병원 일과: 활력징후 측정·회진·식사·면회·샤워 시간대가 움직임을 만듭니다. 임상 악화: 몇 시간에 걸친 악화와 코드블루, 환자 정보의 NEWS2.
      3. 
          
    3. 원외 MCOT: 앱 강제 종료·절전 일괄 업로드·OS 업데이트·비행기 모드. 입퇴원: 요일·시간대 재원 곡선과 대량 유입.
      4. 
          
    4. 재현: [에뮬레이터 설정 › 바이오 월드 생성]에서 시작 시각을 고정하고 1초 고정 간격을 켜면 같은 사건이 같은 순서로 다시 일어납니다. 수동 조작은 시나리오 스크립트의 [녹화]로 저장해 재생합니다.
      5. 
          
    5. 정답 라벨: 데이터 탭에서 리듬 에피소드·신호 품질·임상·장애 구간을 CSV로 내려받아 분석 알고리즘을 채점합니다.

    2. EMR: /emr/hospital|floors|gateways|admissions|patients|patches|layout, DB: POST /api/v1/db/query.
    3. 실시간: ws://host/ws/live + {"rows":[...]}(숫자만 "numeric":true).
    
          
    curl -X POST localhost:5445/api/v1/control/trigger -H 'Content-Type: application/json' -d '{"what":"storm","duration":20}'
    
        
    자동 최적화와 성능
    
          
    1. 대시보드 [자동 최적화]: 환자 수를 단계적으로 올려 안정 최대치를 찾습니다.

    2. Pi: python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt, 최초 python run.py --pregen, 이후 python run.py --port 5445.
