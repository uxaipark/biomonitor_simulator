개요

실제 환자와 병동 없이도, 원격 환자 모니터링 시스템 전체를 운영 규모로 돌려 볼 수 있는 시험대입니다.

웨어러블 패치 기반 모니터링 시스템은 패치, 병동 게이트웨이, 수집(라우터) 서버, 중앙 모니터, 병원 EMR이 이어진 구조입니다. 각 구간은 따로 만들 수 있지만, 수천 명 규모의 동시 트래픽과 병원 현장의 불규칙한 사건(환자 이동, 전극 분리, 장비 교체, 망 장애)은 실제 병동에 들어가기 전에는 재현하기 어렵습니다.

Bio-Signal Emulator는 이 앞단 전체를 소프트웨어로 대신합니다. 병원 건물과 병동을 도면 수준으로 만들고, 환자 프로필과 질환에 맞는 생체신호를 생성하며, 게이트웨이별 TCP 연결로 실제와 같은 바이너리 스트림을 보냅니다. 수집 서버는 이 에뮬레이터를 실제 병원처럼 대하면 됩니다.

병원과 환자

병원 규모는 모니터링할 환자 수에서 거꾸로 정해집니다. 환자 500명이면 628병상 1동 9층, 2,000명이면 2,503병상 3동 20층이 됩니다(병상 여유 20 %).

BUILDING

건축 도면 원형 10종

단일 이중복도형(≤80병상)부터 L·T자, 레이스트랙, 중정형, 십자 4익동, 고층 타워, 분산 포드, 대학병원 다동, 메디컬센터 Y자 트리플 타워(≤5,000병상)까지 병상 수에 맞춰 자동 선택합니다.

CODE

국내 규정 치수 반영

다인실 병상당 6.3 m² 이상, 1인실 10 m² 이상, 병상 간 1.5 m, 신축 병실 최대 4병상, 복도 유효폭 3.0 m, 3층 이상 직통계단 2개소를 생성기가 스스로 검증합니다.

WARD

병동 · 진단부 구성

층마다 두 간호단위(A/B), 간호사실·투약실·청결/오염 처치실·음압 격리실. 1층에는 응급실, CT·MRI(Zone II~IV)·X-ray, 심혈관조영실, 투석실, 내시경, 외래가 들어갑니다.

GATEWAY

게이트웨이 배치 규칙

방마다 천장 중앙에 두되 모든 지점이 도달거리 8.5 m 안에 들도록 늘리고, 로비·대기실은 피크 인원으로 계산해 게이트웨이당 BLE 용량(32)의 75 %를 넘지 않게 추가합니다.

PATIENT

환자 프로필 1만 명

24개 진단(심장 12 · 기타 12), 나이·성별·체격·혈액형·알레르기·동반질환·거주지(동 단위). 한국식 이름은 출생 연대별 작명 경향을 따르고 외국인 환자도 섞입니다.

DAY

병원의 하루

검사 이동(엘리베이터 음영 구간 포함), 병실 이동, 화장실·샤워·재활, 가족 면회, 요일·시간대 재원 곡선, 오전 퇴원·오후 입원, 임상 악화와 코드블루.

원외 모니터링 (MCOT)

원외 환자는 스마트폰형 모바일 게이트웨이로 연결됩니다. 집·외출·음영 구간, 모바일 회선 지연, 단말 배터리 방전과 충전, 앱 강제 종료·절전 모드·OS 업데이트·비행기 모드에 따른 끊김과 일괄 업로드를 흉내 냅니다.

생체신호

런타임에 수학 계산을 하지 않습니다. 모든 파형은 미리 만든 1시간 루프에서 잘라 쓰고, 환자마다 변형·오프셋·게인·노이즈를 조합해 서로 다르게 보이게 합니다.

생리적 일관성

  • 호흡이 RR 간격(RSA)과 ECG 진폭(EDR)을 흔들고, PPG는 맥파 전달 시간만큼 늦게 따라옵니다. 수치와 파형이 같은 출처에서 나옵니다.
  • 다일 변동: 주간 심박·호흡 상승, 저녁 체온 상승, 야간 SpO₂ 저하, 6~71시간 주기 드리프트. 심박 계수는 파형 재생 속도에 그대로 적용되어 파형과 HR이 어긋나지 않습니다.
  • 페이스메이커: 심장 환자의 약 6 %가 이중방(52 %)·단일심실(20 %)·ICD(10 %)·CRT(11 %)·리드리스(5 %)·단일심방(2 %)을 갖습니다. 스파이크 크기는 유니폴라 2~8 mV, 바이폴라 0.08~0.5 mV, 리드리스 0.05~0.25 mV이고 캡처 실패·언더/오버센싱 오작동도 있습니다.
  • 전극: 떨어지는 순간 3초간 크게 요동한 뒤 레일에 포화되고, 다시 붙이면 약 20초 동안 오프셋이 감쇠하며 그 동안 HR·RR은 무효로 표시됩니다.
  • NIBP는 패치 채널이 아니라 병동 간호 스팟체크(커프, 1시간 간격) 모델로 API에서 제공합니다.

기기와 패치 수명

환자마다 증상에 맞는 기기 세트를 달고, 패치는 실제 제품처럼 수명이 있고 교체되면 새 번호를 받습니다.

DEVICE SET

환자별 기기 세트

ECG 패치(항상) + 체온 패치 + SpO₂ 센서(손끝·반지형·손목 PTT 중 하나) + CGM. 자동 정책에서는 호흡기·감염·심부전·심장수술 환자의 92 %가 SpO₂를, 발열·수술·종양 병동 환자의 95 %가 체온 패치를, 당뇨 환자의 95 %가 CGM을 답니다. 패치마다 실제 달린 기기의 채널만 보냅니다.

LIFECYCLE

배터리 15.5일, 최대 착용 14일. 착용 만료·배터리 부족·병실 이동·MRI 촬영 때 교체되고, 교체된 패치는 새 시리얼과 patch_id를 받습니다(재사용 없음). 모든 패치는 레지스트리에 발급·종료 시각과 사유가 남습니다.

유실 판별과 복구

  • 두 종류의 순번: 게이트웨이 프레임 seq의 틈은 게이트웨이→라우터 구간 유실이고, 패치 패킷 seq의 틈은 패치→게이트웨이→라우터 전체 구간 유실입니다. 어느 구간에서 사라졌는지 구분됩니다.
  • 재전송(NACK): 라우터가 같은 소켓으로 요청 구간을 돌려보내면 게이트웨이가 최근 10초(워커당 64 MB)분을 원래 순번 그대로 다시 보냅니다.
  • 저장 후 전송: 회선이 끊긴 동안 게이트웨이별로 최대 2 MB를 쌓아 두었다가, 복구되면 과거 타임스탬프·연속 순번으로 주기당 40프레임씩 버스트 전송합니다.
  • 회선 오류는 TCP가 이미 고치므로 오류정정 부호(FEC)는 쓰지 않습니다. 실제 유실(끊김, 버퍼 넘침)은 재전송과 저장 후 전송으로 다룹니다.

EMR 연동 시험

상용 EMR 연동 코드를 실제 병원에 붙이기 전에 형식 차이, 인증, 오류 응답, 장애를 미리 겪어 볼 수 있도록 가상 의료기관 20곳을 내장했습니다.

국가기관 수형식
미국4FHIR R4 · US Core (2곳, 계열별 검색 제약), HL7 v2.5.1 MLLP + IHE PCD-01, 외래 REST
영국2FHIR R4 · UK Core (NHS 번호, 요청 ID 필수), HL7 v2.4 (NHS ITK 관례)
일본2SS-MIX2 HL7 v2.5 (ISO-2022-JP, 한자·가나 이름), FHIR R4 · JP Core
한국4FHIR R4 · KR Core (KCD-8), 대학병원식 REST JSON, EUC-KR XML 전문, 진료정보교류 CDA R2
독·불·네·호·캐·싱·브·UAE8ISiK, IHE PAM FR (INS·ZBE), FHIR STU3 (zib), AU Core, HL7 v2.3 (OHIP), NRIC, RNDS (CNS·CPF), Malaffi (Emirates ID)
  • 인증 10가지 방식: SMART Backend Services JWT, 서명 JWT, client_credentials(Basic/폼), HTTP Basic, 고정 토큰, API 키, 인증서+CPF, MLLP 기관 라우팅.
  • 현실적인 식별자: NHS·BSN·CPF·CNS·INS·IHI·NRIC·Emirates ID·NPI·OHIP·KVNR·주민번호가 각국 체크 디지트 규칙을 통과하는 합성값입니다. 주민번호는 항상 마스킹합니다.
  • 코드 체계: ICD-10-CM · ICD-10 · KCD-8 · ICD-10-GM · CID-10 · MEDIS 병명 · SNOMED CT, 바이탈은 LOINC · IEEE 11073 MDC · 병원 로컬 코드.
  • 연동 병원 선택: 20곳 중 하나를 고르면 그 병원 EMR이 에뮬레이터의 실제 재원 환자·병상·입퇴원을 자기 형식으로 내주고, 프레임의 환자번호와 그 EMR의 번호를 잇는 조인 키가 제공됩니다.
  • 장애 주입: 병원별 지연, 5xx 비율, 서버 다운, 토큰 수명을 바꿔 재시도·백오프를 시험합니다.
상표 안내 — 기관명은 모두 가공입니다. 표 안의 계열 표기(US Core, SS-MIX2 등)는 표준과 관례를 가리키며, 특정 EMR 회사의 서버·데이터와는 관계가 없습니다.

검증 도구 · API

에뮬레이터는 보내기만 하지 않습니다. 정답을 함께 내주어 수집 서버와 분석 알고리즘을 채점할 수 있게 합니다.

GROUND TRUTH

정답 라벨

부정맥 에피소드·임상 악화·장애 구간을 epoch ms 단위 라벨로 내보냅니다(JSON/CSV). 알람 로직의 민감도·특이도를 계산할 수 있습니다.

RECEIVER

참조 수신기 · 검증기

엄격 모드 수신기가 magic·버전·길이·CRC, 순번 틈·중복·역순, 시각 역행, 알 수 없는 채널을 집계합니다. 라우터 구현의 레퍼런스 디코더입니다.

SCRIPT

재현 가능한 시나리오

시뮬레이션 시각에 맞춰 사건을 재생하는 스크립트와 녹화·재생, 고정 시작 시각·고정 스텝 모드로 회귀 시험을 결정적으로 반복합니다.

DATA

SQLite 이력

입퇴원, 패치 레지스트리, 검사 일정, 게이트웨이 장비 이력, 이벤트, 실행 기록을 저장하고 SELECT 전용 조회 API를 엽니다.

TUNE

자동 최적화

현재 장비에서 오버런 없이 보낼 수 있는 최대 채널 수를 스스로 찾아 설정합니다.

CHAT

연동 채널

에뮬레이터·라우터·운영자가 함께 쓰는 채팅 허브(WebSocket/REST)로 배포 예고와 연동 이슈를 주고받습니다.

운영 화면

반응형 웹 제어판 하나로 전부 다룹니다. 44 px 터치 타깃으로 설계해 7인치 키오스크부터 데스크톱까지 같은 화면을 씁니다.

  • 운영 현황: 전송률·데이터량·연결 상태·이벤트 로그와 라우터가 보고한 수신 상태.
  • 모니터링: 환자 목록(처방 일수·D+n·패치 착용일 포함), 환자 한 명의 실시간 ECG·Pleth·호흡 파형과 수치, 리듬·이벤트 주입, NEWS2.
  • 병원: 층별 건축 도면 위의 침대 점유, 이동 중 환자, 게이트웨이 상태와 커버리지·음영지역, 건물 측면도. 게이트웨이를 누르면 Central Station이 2×1부터 16×10까지 n-up으로 열립니다.
  • 에뮬레이터 설정: 시나리오 프리셋, 시그널 송출(실측 파형 파일 업로드), 메디컬 월드 생성(병원·환자·루프 은행).
  • 테스트: 특정 게이트웨이·환자에게 이벤트를 보내 뷰어의 표시와 경보음을 현장에서 확인.
  • EMR 연동: 20곳 상태, 자체 시험, 예시 요청, 장애 주입, 요청 로그, 수신 바이탈, 연동 병원 선택.
  • 시작 매뉴얼: 101·201·301 단계별 안내와 T-01~T-14 시험 항목. 항목마다 [이 설정 적용] 버튼이 있습니다.

활용 사례

시험 대상에 따라 같은 에뮬레이터를 다르게 씁니다.

수집 서버 부하 · 장기 시험

무장애 기준선으로 2,000명 규모를 며칠 동안 흘려 처리량과 메모리 누수를 확인하고, 드릴로 파서와 재접속 로직을 깨뜨려 봅니다.

중앙 모니터 · 경보 검증

임상 악화·부정맥 에피소드를 주입하고 정답 라벨로 경보 지연과 누락을 채점합니다. 현장 테스트로 특정 게이트웨이 뷰어의 경보음을 확인합니다.

병동 설계 · 커버리지 검토

도면 위 게이트웨이 도달거리와 음영지역, 검사 이동 경로의 핸드오버를 보고 배치를 조정합니다.

EMR 연동 개발

국가·벤더 형식이 다른 20곳을 상대로 인증·식별자 매칭·바이탈 전송·ADT 수신을 구현하고, 연동 병원을 골라 실제 재원 환자로 끝까지 이어 봅니다.

장애 대응 훈련

정전·스위치 장애·게이트웨이 교체를 걸어 운영 절차와 알림 체계를 점검합니다.

시연 · 교육

실제 환자 데이터 없이 병원 규모의 살아 있는 화면을 보여 줍니다. 모든 환자·기관 정보는 합성입니다.

한계 · 로드맵

에뮬레이터가 아직 다루지 않는 부분입니다.

  • ECG는 1채널입니다. 2~3채널 벡터 ECG와 12유도 확장을 검토 중입니다.
  • BLE 끊김 동안 패치 내부에 저장했다가 재접속 후 채워 보내는 백필(back-fill)은 아직 손실로만 모델링합니다.
  • 게이트웨이 클록 드리프트와 NTP 보정 이벤트는 모델링하지 않습니다.
  • 전송 구간의 TLS와 게이트웨이 인증은 제외되어 있습니다(시험망 전제).
  • 원외 환자는 GPS 좌표 없이 집·외출·음영 상태만 제공합니다.
  • EMR 시험 서버의 JWT는 형식과 클레임만 검사하고 서명은 검증하지 않으며, 받은 바이탈은 메모리에만 보관합니다.
